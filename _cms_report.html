BAB I
PENDAHULUAN

1.1 Latar Belakang

Klojen.com adalah portal berita digital yang membutuhkan sistem manajemen konten (CMS) untuk mendukung alur kerja tim redaksi. CMS ini harus mampu menangani seluruh siklus hidup artikel — mulai dari penulisan draf oleh jurnalis, proses review dan penerbitan oleh editor, hingga pengelolaan media, komentar, dan analitik oleh admin.

Sistem CMS Klojen.com dirancang dengan arsitektur Decoupled / Headless CMS, di mana backend (Laravel 12) dan frontend (Next.js 15) terpisah sepenuhnya dan berkomunikasi melalui REST API. Pendekatan ini memungkinkan skalabilitas, fleksibilitas, dan pemeliharaan yang lebih baik.

1.2 Tujuan

  1. Mendokumentasikan arsitektur dan fitur sistem CMS Klojen.com secara lengkap.
  2. Menjelaskan alur kerja redaksi (editorial workflow) dan mekanisme kontrol akses berbasis role.
  3. Mendokumentasikan seluruh endpoint API CMS beserta parameter dan response-nya.
  4. Menyajikan rencana pengujian (test plan) yang komprehensif untuk sistem CMS.

1.3 Ruang Lingkup

Dokumen ini hanya membahas sistem CMS (halaman /cms/*), tidak mencakup portal publik (halaman beranda, artikel publik, pencarian publik). Ruang lingkup meliputi:

  • Dashboard CMS (jurnalis, editor, admin)
  • Manajemen artikel (CRUD, status, lock/unlock, scheduled publishing)
  • Manajemen media (upload, galeri, library)
  • Moderasi komentar
  • Manajemen user (karyawan, pengguna)
  • Manajemen kategori dan tag
  • Profil user dan autentikasi JWT

BAB II
ARSITEKTUR SISTEM CMS

2.1 Arsitektur Keseluruhan

Sistem CMS Klojen.com terdiri dari tiga lapisan utama: Frontend (Next.js 15), Backend REST API (Laravel 12), dan Database (MySQL 8). Komunikasi antar lapisan dilakukan melalui HTTP/JSON dengan autentikasi JWT.

BAB IV
ALUR KERJA REDAKSI
(EDITORIAL WORKFLOW)

4.1 State Machine Status Artikel

Setiap artikel memiliki status yang mengikuti state machine berikut. Transisi status divalidasi di CmsArticleService::updateStatus().

Business Rules

KodeAturan
BR-01Artikel baru selalu berstatus draft
BR-02Jurnalis hanya bisa mengubah status draft → review (artikel miliknya)
BR-03Editor/Admin bisa mengubah review → published / scheduled / draft
BR-04scheduled_at harus minimal 5 menit dari sekarang
BR-05Artikel published hanya bisa diubah ke archived
BR-06Artikel draft bisa dihapus; status lain tidak bisa dihapus

4.3 Mekanisme Lock/Unlock Artikel

Fitur Lock mencegah konflik editing simultan. Kolom locked_by di tabel articles menyimpan ID editor yang sedang mengerjakan artikel.

AksiEndpointRoleValidasi
LockPUT /api/cms/articles/:id/lockEditorTidak boleh lock artikel yang sudah di-lock editor lain
UnlockPUT /api/cms/articles/:id/unlockEditorHanya editor yang lock bisa unlock

4.4 Scheduled Publishing

Artikel dengan status scheduled akan otomatis diterbitkan pada waktu yang ditentukan. Proses ini dijalankan oleh Artisan command articles:publish-scheduled yang dipanggil via cron job.

  • Tabel scheduled_articles menyimpan jadwal terbit setiap artikel
  • ScheduledPublishService mengecek artikel yang sudah waktunya terbit
  • Status otomatis berubah dari scheduled ke published
  • Field published_at dan published_by diisi saat terbit

5.2 Bank Berita

Halaman /cms/artikel menampilkan daftar artikel. Jurnalis hanya melihat artikel miliknya, editor/admin melihat semua artikel. Fitur: pencarian, filter status, filter kategori, pagination, dan aksi cepat (edit, hapus, ubah status).

5.3 Tulis Berita

Halaman /cms/tulis-berita dan /cms/artikel/baru menyediakan form lengkap untuk menulis artikel baru:

  • Judul — auto-generate slug dari judul
  • Konten — rich text editor (HTML)
  • Kategori — pilih dari daftar kategori
  • Tags — input multiple, auto-create jika belum ada
  • Featured Image — upload gambar utama
  • Excerpt — ringkasan singkat (max 1000 karakter)
  • Media Library — sisipkan gambar dari media tersimpan
  • Status otomatis: draft

5.4 Tinjauan Artikel

Halaman /cms/tinjauan-artikel khusus untuk Editor dan Admin. Menampilkan artikel dengan status review yang perlu ditinjau. Editor bisa melakukan:

  • Melihat detail artikel
  • Lock/unlock artikel
  • Edit konten artikel
  • Publish, schedule, atau reject artikel

5.5 Media Tersimpan

Halaman /cms/media mengelola galeri media (gambar). Fitur:

  • Upload gambar baru (multipart/form-data)
  • Galeri grid dengan pagination
  • Filter berdasarkan kategori media
  • Hapus media
  • Dual mode: is_library=true untuk media bank global, is_library=false untuk media terikat artikel

5.6 Komentar & Moderasi

Halaman /cms/komentar untuk moderasi komentar (Editor/Admin):

  • Daftar semua komentar dengan informasi artikel dan user
  • Pagination (20 per halaman)
  • Hapus komentar yang tidak pantas
  • Komentar mendukung threading (max 2 level)

5.7 Manajemen Karyawan & Pengguna

Khusus Admin. Terbagi dua halaman:

HalamanTarget UserFitur
/cms/karyawanJurnalis, Editor, AdminCRUD karyawan, kirim kredensial via email
/cms/penggunaReader (pembaca)CRUD pengguna, aktifkan/nonaktifkan akun

5.8 Kategori & Tag

Khusus Admin. Halaman /cms/kategori mengelola:

  • Kategori — hierarchical (parent-child), auto-generate slug
  • Tag — flat structure, auto-generate slug
  • CRUD: tambah, edit, hapus

BAB VI
DATABASE CMS

6.1 Tabel Utama CMS

TabelPrimary KeyKeterangan
articlesUUIDTabel utama artikel: judul, slug, konten, status, author, lock
usersBIGINT AUTO_INCREMENTData user: name, email, password, role, is_active, avatar
categoriesUUIDKategori hierarchical (parent_id self-ref)
tagsUUIDTag artikel (name, slug)
article_tagsComposite (article_id, tag_id)Relasi many-to-many artikel-tag
article_revisionsUUIDAudit trail: snapshot title & content setiap perubahan
scheduled_articlesUUIDJadwal terbit: article_id, scheduled_at, is_published
mediaUUIDFile media: URL, alt_text, is_library, category_name
commentsUUIDKomentar: content, status, parent_id (threading)
search_indexesUUIDFULLTEXT index untuk pencarian artikel
page_viewsBIGINTTracking visitor: IP, path, viewed_at

6.2 Relasi Antar Tabel

  • articles → users: author_id (penulis), published_by (penerbit), locked_by (editor yg lock)
  • articles → categories: category_id (many-to-one)
  • articles → tags: via tabel article_tags (many-to-many)
  • articles → article_revisions: one-to-many (setiap edit = 1 revision)
  • articles → scheduled_articles: one-to-one (jika status = scheduled)
  • articles → media: one-to-many (gambar terikat artikel)
  • articles → comments: one-to-many (cascade delete)
  • comments → comments: self-ref via parent_id (threading, cascade delete)
  • categories → categories: self-ref via parent_id (hierarchical)
